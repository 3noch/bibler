# bible-tags

Tag-painting Bible reader. Local-first Solid.js client, Rust server, SQLite.

## Layout

    fixtures/normalize.json     shared test vectors (the behavioral spec for paint/erase)
    fixtures/refs/parse.json    reference parser cases
    fixtures/text/              golden checks for the frozen KJV tokenization
    data/source/eng-kjv2006/    vendored KJV USFM (input of text-build; never edit)
    docs/text-format.md         tokenizer spec + artifact formats
    packages/scripture/         TypeScript: normalize, book table, TextIndex, reference parser/formatter
    crates/normalize/           Rust twin of normalize (server will depend on it)
    crates/text-build/          USFM -> tokens, index.bin, per-book JSON, manifest (build/text/)
    crates/ops/                 what an op does to a user's rows (canonical; TS twin in packages/scripture)
    crates/server/              axum + SQLite: client, text artifacts, sessions, sync WebSocket; in-process TLS
    packages/app/               Solid client: reader, tag painting, offline-first sync
    fixtures/ops.json           ops spec (generated by fixtures/ops.py)
    Makefile / default.nix      dev workflow / production build

## Decisions locked so far

- Text is addressed by **word ordinals**, intervals are **half-open** `[start, end)`.
- Per `(owner, tag)`, taggings are **disjoint and non-adjacent**. Painting merges; erasing trims/splits.
- Merge survivor = oldest tagging by `(created_at, id)`; comments of merged taggings move to it
  (displayed by timestamp). Erase-split: left piece keeps id + comments; right piece gets a
  client-supplied `split_id` and the original `created_at`.
- `normalize` is pure and deterministic. Ids it may need are supplied by the client in the intent.
- No WASM: logic is duplicated in TS and Rust and kept honest by shared fixtures + property tests.
- Psalm titles are verse slot 0 (the source has them as `\d`). Apocrypha is not in `kjv-1769-v1`.

## Running

    nix-shell            # node for the dev tools (Rust comes from rustup / rust-toolchain.toml)
    make dev             # http://localhost:5173 (Vite + HMR, proxying to the Rust server on :8080)
    make serve           # production-like on http://localhost:8080
    make test            # Rust + TS tests        make check   fmt, clippy, typecheck

    nix-build -A app     # production build: result/bin/bible-tags
    result/bin/bible-tags --db /var/lib/bible-tags/db.sqlite --addr 0.0.0.0:443 \
                          --tls-cert fullchain.pem --tls-key key.pem --http-redirect 0.0.0.0:80

## Status

- normalize: 28 shared fixtures + a 200x150-step randomized property run pass in BOTH TS and Rust;
  rustfmt/clippy/tsc clean. Both suites were mutation-checked (adjacency, survivor age and id tie-break,
  comment move, split-piece age, erase-abut, no-op update, output sort orders): every mutation is caught.
- text: KJV tokenized (790,676 tokens, 32,291 verse slots), golden-checked, cross-checked against an independent
  Python tokenizer. TS index round-trips every ordinal.
- refs: 180+ fixture cases, every alias, every chapter's last verse, and 3,500 random format->parse round trips.
- sync: own per-owner event log. Ops -> canonical row changes (Rust + TS twins, 53 shared fixtures, property tests
  incl. undo-all), SQLite store, WebSocket replay + fan-out, offline outbox shared across tabs, undo/redo via
  revert. End-to-end WebSocket tests, a 3-client convergence property test, and a two-tab browser test.
